# Subagent task 03 — Markdown renderer

**Branch:** `task/03-markdown-renderer` (off `feature/v0-architecture`
after PR #1 merges, or off `main` if PR #1 + PR #2 are both in)
**Goal:** Add a pure-Markdown renderer that emits one `.md` file per
`AbapObject` and self-registers via the new
`@abapdoc/renderer-registry`. After this lands, the CLI's
`--format all` will produce 14 files (10 existing + 4 `.md`).

## Why

We have HTML (self-contained site), MDX (Markdown with JSX-significant
escaping for Starlight), and JSON (round-trippable model dump). The
missing one is plain Markdown — useful for GitHub-rendered READMEs,
static-site generators that don't grok MDX, and pasting into chat
without JSX artefacts.

The renderer registry introduced in PR #2 means adding this format
requires **no CLI changes** beyond:

1. Adding `'markdown'` to `SUPPORTED_FORMATS` in
   `packages/abapdoc-renderer-registry/src/registry.ts`
2. Creating the new package
3. Letting the CLI's side-effect import pick it up

## Public surface (new package `packages/abapdoc-renderer-markdown/`)

Mirror the structure of the existing renderers. Public API:

```typescript
export function render(
  model: DocumentationModel,
  options?: RenderOptions
): RenderResult;
```

Where `RenderOptions` and `RenderResult` match the other renderers
(`{ files: Array<{ path, content }> }`).

The package must self-register on import:

```typescript
import { registerRenderer } from '@abapdoc/renderer-registry';
// ... at module top level, after the render function definition:
registerRenderer({ format: 'markdown', render });
```

The renderer's own `package.json` lists `@abapdoc/renderer-registry`
as a dependency and its `tsconfig.json` references the registry's
`tsconfig.lib.json`.

## Required tests (5+)

1. `renders a class object to a markdown file with a heading and
a description`
2. `renders a function module to a markdown file with parameters
and exceptions`
3. `renders a table to a markdown file with a GFM fields table`
4. `emits one file per AbapObject, no extras`
5. `registers itself as 'markdown' on import (verifiable by
importing the package and calling getRenderer('markdown'))`
6. (optional) `escapes markdown-significant characters in DocBlock
descriptions (e.g. pipes, asterisks)`

## File scope (allowed)

- `packages/abapdoc-renderer-markdown/**` (new package)
- `packages/abapdoc-renderer-registry/src/registry.ts` (add
  `'markdown'` to `SUPPORTED_FORMATS`)
- `packages/abapdoc-cli/src/index.ts` (add side-effect import for
  the new renderer; **no other CLI changes** — the registry
  dispatch already handles the new format)
- `packages/abapdoc-cli/package.json` (add `@abapdoc/renderer-markdown`
  workspace dep)
- `tsconfig.json` (add the new package to root references)
- `package-lock.json` (regenerated by `npm install`)

## Forbidden

- No new third-party deps.
- No touching `@abapdoc/parser`, `@abapdoc/extractor`, or
  `@abapdoc/model`.
- No touching the existing renderers (`renderer-json`,
  `renderer-html`, `renderer-mdx`).
- No `setTimeout` / `setInterval` in tests.
- No changing the public API of the registry or the existing
  renderers.

## Settlement rules

- Output file extension is `.md`, not `.markdown`. Path is the
  kebab-cased object name (same convention as HTML/MDX):
  `zcl-pet-service.md`.
- Pure GFM Markdown: `#` headings, `| col | col |` tables,
  `-` bullet lists, `` `code` `` inline, fenced ` `code` ` blocks.
  No JSX, no frontmatter (MDX has those; markdown doesn't).
- Each file has a single H1 heading with the object name, an H2
  badge-style subheading with the kind, then the DocBlock summary
  / description / tags.
- The renderer's `render` function must be a pure transformation
  (no I/O) — same contract as the existing renderers.
- After the renderer lands, the CLI's `--format all` must produce
  14 files (10 from JSON/HTML/MDX + 4 `.md`).
- The CLI's `--format markdown` alone must produce only `.md`
  files (no `.html`, no `.mdx`, no `model.json`).

## Hints / pitfalls

- The new package **must have a `build` target** (Rule 11). Mirror
  `abapdoc-renderer-registry`'s `project.json` (it has `@nx/js:tsc`
  with the right outputs/options).
- **Must add `'markdown'` to `SUPPORTED_FORMATS`** in
  `packages/abapdoc-renderer-registry/src/registry.ts`. The
  `registerRenderer` validation rejects unknown formats.
- **The CLI's side-effect import must be added** for the new
  renderer package — otherwise the registry is empty for the
  new format at runtime.
- The CLI's `validateFormat` reads `listRenderers()` so it
  picks up `'markdown'` automatically — no change needed there.
- Pattern-match `@abapdoc/renderer-mdx` for the renderer layout
  (escape helpers, page-level builders, group-by-kind) but skip
  the MDX-specific bits (frontmatter, `escapeMdxBody`).
- Pipe characters in DocBlock descriptions will break GFM tables.
  Either escape `|` as `\|` or use HTML entities. The simpler
  choice is the latter (`&#124;`), which renders correctly in
  GitHub-flavoured Markdown and most other renderers.
- The renderer must NOT generate `index.md` — same convention as
  MDX (each file stands alone; consumers build their own landing).
